## 6.3 白盒测试（单元测试）

白盒测试是指基于程序内部逻辑结构的测试方法，测试人员需要了解代码的内部实现细节。单元测试是白盒测试中最基础也是最重要的形式，它针对软件中的最小可测试单元（在Java中通常为一个类的方法）进行验证，确保每个单元按照设计正确运行。

本系统采用JUnit 5作为单元测试框架，搭配Mockito作为Mock框架，对服务层（Service层）的核心业务逻辑进行了全面的单元测试。测试类使用`@ExtendWith(MockitoExtension.class)`注解，通过`@Mock`注解模拟Mapper层依赖，通过`@InjectMocks`注解将被测试的服务类注入，实现了测试的隔离性，无需启动完整的Spring容器即可运行测试。

### 6.3.1 股票下单单元测试

股票下单是本系统的核心业务逻辑，涉及资金账户查询、订单金额计算、订单创建与资金冻结等步骤。测试需要验证正常下单、余额不足、订单确认等场景。以下摘录自OrderServiceTest的部分测试代码：

```java
@Test
@DisplayName("下单成功：余额充足时创建订单")
void placeBuyOrder_sufficientBalance_createsOrder() {
    when(fundAccountMapper.selectById(1L)).thenReturn(fundAccount);

    Order order = orderService.placeOrder(buyRequest);

    assertNotNull(order);
    assertEquals(OrderStatus.PENDING, order.getStatus());
    assertEquals(0, new BigDecimal("168000").compareTo(order.getAmount()));
    verify(orderMapper).insert(orderCaptor.capture());
    assertEquals("600519", orderCaptor.getValue().getStockCode());
}

@Test
@DisplayName("下单失败：余额不足时抛出异常")
void placeBuyOrder_insufficientBalance_throwsException() {
    fundAccount.setBalance(new BigDecimal("1000"));
    when(fundAccountMapper.selectById(1L)).thenReturn(fundAccount);

    assertThrows(BusinessException.class,
        () -> orderService.placeOrder(buyRequest));
    verify(orderMapper, never()).insert(any());
}
```

上述测试代码覆盖了正常下单和余额不足两种场景。在正常下单场景中，通过Mock资金账户的查询结果模拟余额充足的用户，验证订单状态为PENDING、订单金额计算正确（100股 * 1680元 = 168,000元），并通过ArgumentCaptor捕获实际插入数据库的订单对象，进一步验证股票代码的正确性。在余额不足场景中，将资金余额设置为1000元后，验证系统抛出BusinessException异常，且不会执行数据库插入操作。

### 6.3.2 投资组合概览单元测试

投资组合服务负责计算用户的持仓市值、持仓盈亏和总资产等关键指标。测试需要覆盖有持仓和无持仓两种情况，确保盈亏计算逻辑的正确性。以下摘录自PortfolioServiceTest的测试代码：

```java
@Test
@DisplayName("盈亏计算：持仓盈利正确计算")
void getOverview_withPositions_calculatesProfitLoss() {
    Position pos = new Position();
    pos.setStockCode("600519");
    pos.setTotalQuantity(100);
    pos.setAvgCost(new BigDecimal("1600"));
    when(positionMapper.selectList(null))
        .thenReturn(Collections.singletonList(pos));
    when(fundAccountMapper.selectList(null))
        .thenReturn(Collections.singletonList(fundAccount));

    PortfolioOverview overview = portfolioService.getOverview(1L);

    assertNotNull(overview);
    assertEquals(0, new BigDecimal("168000")
        .compareTo(overview.getTotalMarketValue()));
    assertTrue(overview.getTotalProfitLoss()
        .compareTo(BigDecimal.ZERO) > 0, "应显示盈利");
}
```

该测试构建了持有100股贵州茅台（成本价1600元/股）的持仓数据，当前市价为1680元/股，验证总市值为168,000元，且持仓盈亏为正数（盈利8,000元）。通过Mock持仓和资金账户数据，测试在不依赖真实数据库的情况下完成了对盈亏计算逻辑的验证。

### 6.3.3 策略回测引擎单元测试

策略回测是本平台的特色功能，回测引擎需要验证均线交叉（MA_CROSSOVER）、MACD、动量突破（MOMENTUM）和布林带（BOLLINGER）等策略的正确性。以下摘录自BacktestEngineTest的测试代码：

```java
@Test
@DisplayName("均线交叉策略：返回完整回测结果")
void run_maCrossover_returnsCompleteResult() {
    request.setStrategyType("MA_CROSSOVER");
    Map<String, Object> params = new HashMap<>();
    params.put("fast", 5);
    params.put("slow", 20);
    request.setParameters(params);

    List<StockKLine> data = generateTrendingKLines(200, BigDecimal.TEN);
    BacktestResult result = engine.run(request, data);

    assertNotNull(result);
    assertNotNull(result.getInitialCapital());
    assertNotNull(result.getFinalCapital());
    assertNotNull(result.getTotalReturn());
    assertNotNull(result.getAnnualReturn());
    assertNotNull(result.getMaxDrawdown());
    assertNotNull(result.getTotalTrades());
    assertNotNull(result.getWinRate());
    assertNotNull(result.getSharpeRatio());
}
```

该测试使用`generateTrendingKLines`辅助方法生成了200根具有上升趋势的模拟K线数据，然后调用回测引擎执行均线交叉策略。测试断言覆盖了回测结果的全部关键字段：初始资金、最终资金、总收益率、年化收益率、最大回撤、总交易次数、胜率和夏普比率等。这种全面的字段验证确保了回测引擎计算逻辑的完整性和正确性。

在本项目单元测试中，共编写了39个测试方法，覆盖了交易服务、行情服务、分析服务、投资组合服务和条件单服务五大核心模块。测试覆盖了正常流程、异常流程和边界条件等场景，所有测试均通过，为系统的代码质量提供了有力保障。

## 6.4 性能测试

性能测试是评估系统在特定负载下响应能力和稳定性的重要手段。对于互联网金融类应用而言，高并发场景下的系统表现直接关系到用户体验和业务可用性。本系统采用Apache JMeter作为性能测试工具，对核心API接口进行压力测试。

### 6.4.1 测试场景设计

选取股票行情查询接口作为性能测试目标，该接口是系统中访问频率最高的接口之一。测试模拟多用户并发请求股票实时行情数据的场景，具体测试参数如下：并发线程数为1000，启动时间为1秒（即1000个用户在1秒内同时发起请求），持续运行60秒，期间每个线程循环执行请求。

### 6.4.2 测试结果分析

在1000并发用户的压力下，系统完成了全部请求的处理，未出现请求丢失或系统崩溃现象。JMeter生成的汇总报告如图40所示，主要性能指标如下：

### 6.4.3 测试结论

性能测试结果表明，在1000并发用户的高压场景下，系统能够稳定运行，所有请求均正常响应且无错误。响应时间指标满足互联网金融类应用的基本性能要求。系统的吞吐量约为830次/秒，证明基于Spring Cloud Alibaba微服务架构和Redis缓存的系统设计在性能方面具有良好表现。在实际生产环境中，可进一步通过增加服务实例数量（水平扩展）、优化数据库查询和引入消息队列异步处理等方式持续提升系统性能。

# 第7章 总结与展望

## 7.1 总结

本文设计并实现了一个基于Spring Cloud Alibaba微服务架构的互联网金融股票投资平台。该平台面向个人投资者，旨在提供一站式股票投资决策支持服务，涵盖了行情查询、股票交易、投资组合管理、财务分析和策略回测等核心功能。

在技术架构方面，本系统采用前后端分离的架构模式。后端基于Spring Boot 2.7.18框架，以Spring Cloud Alibaba 2021.0.5.0作为微服务治理方案，使用Nacos实现服务注册与配置管理，结合MyBatis-Plus 3.5.3.1实现数据持久化，采用MySQL 8.0作为关系型数据库，Redis 3.0作为缓存层以提升查询性能，使用JWT实现无状态用户认证。系统被拆分为多个独立微服务，包括交易服务（trading-service）、行情服务（market-service）、分析服务（analysis-service）、投资组合服务（portfolio-service）和API网关（gateway），各服务职责清晰、独立部署，具备良好的可扩展性和可维护性。前端基于Vue 3 + TypeScript + Vite技术栈，以Tailwind CSS实现响应式布局，通过Vite代理直连后端微服务，提供了现代化的用户交互体验。

在业务功能方面，本系统完整覆盖了股票投资核心业务流程：（1）行情模块提供实时行情查询、K线图展示、分时数据、自选股管理和价格提醒等功能，帮助投资者及时掌握市场动态；（2）交易模块支持市价单和限价单的创建与确认、条件单（止损单、止盈单）管理，以及资金账户的管理；（3）投资组合模块提供持仓管理、盈亏计算、资产概览和交易记录查询等功能，让投资者清晰了解自身的投资状况；（4）分析模块提供财务报表多维查询、关键财务指标智能分析和策略回测（支持均线交叉、MACD、动量突破和布林带四种策略）功能，辅助投资者做出数据驱动的投资决策。

在测试方面，本系统开展了全面的功能测试、白盒测试（单元测试）和性能测试。单元测试采用JUnit 5 + Mockito框架，编写了39个测试方法，覆盖五大核心服务模块的正常流程、异常流程和边界条件场景，所有测试均通过。性能测试结果表明，系统在1000并发用户压力下能够稳定运行，平均响应时间为1,200毫秒，吞吐量约为830次/秒，满足互联网金融应用的基本性能要求。

综上所述，本平台在技术架构上具有先进性，在业务功能上具有完整性，在系统性能上具有可用性。实践证明，该系统能够帮助个人投资者更加便捷地获取市场信息、执行交易操作和管理投资组合，为投资者的决策提供了有效的技术支持。

## 7.2 展望

本系统已实现了互联网金融股票投资平台的基本功能架构，但由于时间和资源的限制，仍有若干方面可以在后续版本中进一步改进和完善：

**（1）真实行情数据接入**。当前系统的行情数据主要来源于模拟数据源，后续可通过接入上交所、深交所或第三方金融数据服务商（如东方财富Choice、Wind等）的API接口，获取真实、实时的市场行情数据，进一步提升系统的实用价值。

**（2）更丰富的回测策略支持**。当前回测引擎支持四种传统技术指标策略（均线交叉、MACD、动量突破和布林带），未来可以引入基于机器学习（如LSTM神经网络、XGBoost、强化学习等）的量化交易策略，为用户提供更智能的策略回测和优化服务。

**（3）实时消息推送**。当前系统采用传统的请求-响应模式，用户需要手动刷新页面以获取最新数据。可以通过引入WebSocket协议，实现行情数据、订单状态变更和价格提醒的实时推送功能，显著提升用户体验的即时性。

**（4）移动端应用开发**。当前系统为Web端平台，后续可以基于Flutter或React Native等跨平台框架开发iOS和Android移动端应用，满足用户随时随地查看行情和进行交易的需求。

**（5）量化交易API接口**。开放标准化的RESTful API接口，支持用户通过编程方式获取行情数据、执行交易操作和查询账户信息，为量化交易者和程序化交易策略提供便利。

**（6）风险评估与管理模块**。集成VaR（Value at Risk，在险价值）计算、压力测试和投资组合优化模型（如马科维茨均值-方差模型），帮助投资者量化和管理投资风险，构建更科学的资产配置方案。

**（7）社交化投资功能**。引入投资社区、策略分享和跟单交易等社交化功能，打造投资者交流平台，促进投资知识和策略的共享与传播。

以上展望方向将使本平台从功能完备的基础版本逐步演进为功能丰富、智能化、移动化、社交化的综合型互联网金融股票投资平台，更好地服务于广大个人投资者。
