## Context

个人投资者需要一个完整的股票投资平台，集交易与基本面分析于一体。目前市场上交易工具和分析工具分离，投资者需要在多个平台间切换，操作繁琐且无法形成统一的投资视角。

本项目采用微服务架构，面向个人投资者，提供股票交易、持仓管理、财务分析、估值计算等核心功能。

**技术选型：**
- JDK8 + Spring Boot + Spring Cloud (Alibaba)
- Nacos：服务发现与配置管理
- MySQL 8.0：关系型数据存储
- Redis：Token、验证码、缓存
- MinIO：文件存储（头像等）

## Goals / Non-Goals

**Goals:**
- 提供完整的股票交易流程（搜索→下单→确认→持仓）
- 支持基本面分析（财务报表、营收、估值指标）
- 提供技术分析工具（K线、均线、MACD等）
- 投资组合管理和收益追踪
- 数据本地存储，保护用户隐私

**Non-Goals:**
- 非真实交易（模拟交易，不连接真实交易所）
- 多用户/服务端部署
- 港股/美股等其他市场
- 量化交易策略自动化执行

## Decisions

### 1. 技术栈：JDK8 + Spring Boot + Spring Cloud (Alibaba)

**选择理由：**
- JDK8：稳定可靠，企业级项目首选
- Spring Boot 2.7.x：成熟的微服务框架，简化配置
- Spring Cloud Alibaba：完善的微服务生态，与阿里云生态无缝集成

**替代方案：**
- Spring Boot 3.x + Java 17+：需升级JDK，暂无必要
- 纯Spring Cloud Netflix：已停止维护，Spring Cloud Alibaba是更好的选择

### 2. 服务发现：Nacos

**选择理由：**
- 集服务发现和配置管理于一体
- 支持临时实例和持久实例
- 提供可视化控制台
- 与Spring Cloud Alibaba无缝集成

**替代方案：**
- Consul：功能类似但Nacos更轻量
- Eureka：已停止维护

### 2. 数据库：MySQL 8.0

**选择理由：**
- 关系型数据库，事务支持完善
- 社区成熟，文档丰富
- 适合存储用户、订单、持仓、财务数据

**替代方案：**
- PostgreSQL：功能类似，MySQL更普及
- SQLite：单机可用，但无法支持微服务架构

### 3. 缓存：Redis

**选择理由：**
- 存储用户Token，支持快速验证
- 存储图形验证码，支持过期销毁
- 支持分布式Session

**替代方案：**
- Memcached：功能类似但功能较少
- 本地缓存：无法跨节点共享

### 4. 文件存储：MinIO

**选择理由：**
- S3兼容协议，易于集成
- 部署简单，支持高可用
- 适合存储头像等小文件

**替代方案：**
- 阿里云OSS/七牛云：需要第三方服务
- 数据库BLOB：性能较差

### 5. 前端：Vue + Element Plus

**选择理由：**
- 组件丰富，快速构建后台管理界面
- 图表库（ECharts）支持K线和技术指标
- 前后端分离，便于微服务调用

### 6. 行情数据：东方财富/新浪财经免费接口

**选择理由：**
- 免费，无需API费用
- 数据较全面
- 有官方Python/JS SDK

**替代方案：**
- 付费专业数据源（Wind/同花顺）：成本高
- 交易所直连：需要牌照

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| 免费行情数据不稳定 | 添加本地缓存，请求失败时展示缓存数据 |
| MySQL单点故障 | 配置主从复制或使用高可用方案 |
| Redis数据丢失 | 配置RDB/AOF持久化 |
| MinIO存储扩容 | 预设存储容量规划，支持平滑扩容 |
| Nacos单点故障 | 配置Nacos集群（推荐3节点） |
